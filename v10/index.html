你的任务是分析我上传的这张参考图片，并为我生成一段结构化的图片生成提示词，目标是让即梦能够最大程度上复现原图的风格、内容和构图。

#分析维度，请按照以下结构和要求输出分析结果:
1.核心主体:描述图片中最主要的人物、物体或焦点，包括其外观、姿态等细节。
2.场景环境:描述图片所处的环境背景。具体是什么样的场景?背景中有什么关键元素?
3.构图视角:描述画面的构图方式、摄影机位和视角(如特写、鸟瞰、仰视、2.5D等)。
4.光照氛围: 描述整体的光线效果(如自然光、霓虹灯)、光线方向、质感，以及画面的整体氛围(如科技感)。
5.风格:描述图片的风格。是照片级写实、3D渲染，还是其他风格?
6.色调与色彩搭配 : 描述图片的主色调和色彩搭配。颜色是鲜艳饱和还是柔和复古?整体色调是偏暖还是偏冷?
7.文字与图形:识别画面中包含的主体文字或图形。记录其内容和精准位置。
8.细节与质感 : 提及画面中值得注意的背景、装饰和材质细节。

#最终任务
请将以上所有分析结果，整合成一段可以直接使用的、完整的、高质量的中文提示词，600 字以内。以 markdown 代码框格式输出。

不要遗漏任何关键信息，关键词用逗号分隔，并在末尾附上推荐的图像比例参数。

第六章

提示词技巧清单

• 参考图优先：开头写“严格参考上传图片的视觉风格”。

• 主体公式：主要对象、辅助对象、装饰元素，表达功能语义。

• 顺序优先：越靠前的提示词权重越高。

• 分行组织：按维度分行，结构更清晰。

• 风格固定：统一视角、材质、光照和色彩。

• 文字渲染：文字内容放入英文双引号中，如 "DATA"。

• 数值约束：使用具体范围，如占画面 35% 到 45%。

• 负面约束：明确写出禁止项，如无文字、无杂物。

• 权重控制：使用 (关键词:1.2) 强化重点，用 [关键词] 弱化内容。

• 同义叠加：多个近义词组合，提高稳定性。

• 单图更稳：一次生成 1 张比组图更容易复刻。

• 适度精简：避免过长，突出关键要求。

• 局部编辑：使用“将图 1 的材质改为参考图 2 的材质”类指令。

• 多次迭代：先验证风格，再批量生成。

标签宽度规范
当表单标签采用右对齐时，同一表单区域内的标签宽度应保持一致，避免因标签文字长度不同导致左侧起始位置参差不齐，影响表单整体对齐和阅读效率。
标签宽度可根据当前表单区域内最长标签确定，但应受统一上限约束：
标签宽度 = min(当前表单区域最长标签宽度, 120px)
规范要求：
- 同一页面、同一分组或同一表单区域内，标签宽度必须统一。
- 不同表单页面可根据字段长度采用不同标签宽度，但应保持在系统定义的宽度范围内。
- 标签最大宽度建议不超过 120px。
- 当标签内容超过最大宽度时，可采用省略号显示；必要时可通过悬浮提示展示完整内容。
- 不建议因个别超长标签扩大整个表单标签宽度，避免压缩输入区域或破坏页面布局。
推荐宽度档位：
72px / 96px / 120px
使用建议：
- 字段名称较短、结构简单的表单，可使用 80px。
- 常规业务表单，推荐使用 96px。
- 字段名称较长或政务、监管、档案类表单，可使用 120px。
- 超过 120px 的标签应进行文案精简或省略处理。

10.1 agent分析的具体过程

10.1 agent分析的具体过程

使用当前图片作为唯一参考图，严格复刻其版式、信息层级、配色和构图，生成一张超高清中文产品设计规范海报。重点修正：所有中文文字、数字、图标和表单示例必须保持原始宽高比，禁止任何横向或纵向拉伸，禁止字体被压扁或拉长，确保字形自然、标准、清晰可读。所有文本使用正常字宽（100% horizontal scale, 100% vertical scale），字符间距、行距、段落间距均保持均衡，避免字形变形。

【整体风格】
- 专业的企业级 UI/UX 设计规范海报
- 白色到浅灰色的干净背景，轻微渐变
- 大量留白，布局规整，对齐精准
- 中文排版清晰锐利，类似微软雅黑 / PingFang SC / Source Han Sans SC
- 所有字体均使用 Regular / Semibold / Bold 的正常字宽，不使用 Condensed、Expanded 或任何非标准缩放
- 4K 超清，矢量质感，印刷级清晰度
- 所有元素边缘锐利，无模糊，无锯齿

【关键排版要求（最重要）】
- 禁止文字横向拉伸（no horizontal stretch）
- 禁止文字纵向拉伸（no vertical stretch）
- 禁止整体内容比例失衡（no distorted aspect ratio）
- 保持字体宽高比 1:1（normal glyph proportions）
- 中文字形必须方正自然，不瘦长、不扁宽
- 数字与单位（72px、96px、120px）保持标准比例
- 标题、正文、标签、公式、注释全部使用正常字体比例
- 输出画布比例必须与参考图完全一致，不得改变纵横比
- 所有模块保持正确尺寸关系，不允许整体被纵向压缩或横向拉伸

【画布设置】
- Portrait vertical poster
- Aspect ratio exactly the same as the reference image

# 设计规范图生成方法论与通用提示词

> 用途：当你有一篇设计规范初稿时，把这份方法论和提示词一起发给大模型，让它把文字规范转化为一张或一组设计规范图。

## 一、设计规范图的本质

设计规范图不是“把文字排成海报”，而是把一条规则转化为可被快速理解、复用和执行的视觉说明。

一张合格的设计规范图需要同时解决四个问题：

```text
1. 这条规范解决什么问题？
2. 正确规则是什么？
3. 规则在界面里具体落在哪里？
4. 什么情况下适用，什么情况下不适用？
```

因此，设计规范图应该同时具备：

- 规则性：表达明确的设计约束。
- 场景性：展示规则适用的真实 UI 场景。
- 可视化：用框、线、箭头、示例、对比降低理解成本。
- 可执行：设计师、研发、评审人员看完后能直接按规则落地。

## 二、设计规范图的关键要素

### 1. 标题要素

标题负责让读者立即知道这张图讲什么。

推荐结构：

```text
规范对象 + 规则动作 + 约束目标
```

示例：

```text
表单标签宽度规范
查询项默认数量与响应式断点规则
表格操作列冻结与视图控制规范
上传组件图片展示与操作规范
```

标题不宜写成抽象口号，而应该明确指向组件和规则。

### 2. 问题说明

问题说明回答“为什么需要这条规范”。

它通常包含：

- 当前设计中存在的问题。
- 问题导致的体验影响。
- 不规范实现可能带来的协作成本。

推荐句式：

```text
当 [组件/场景] 出现 [不一致/拥挤/错位/信息不清] 时，会导致 [视觉问题/阅读效率下降/操作成本增加]。
```

### 3. 核心规则

核心规则是整张图的中心，必须突出显示。

常见表达方式：

- 公式卡片
- 规则卡片
- 判断条件
- 推荐值
- 最大值 / 最小值
- 优先级顺序

示例：

```text
标签宽度 = min(当前表单区域最长标签宽度, 120px)
查询项默认展示数量 = min(页面可容纳数量, 5)
操作列固定在右侧，宽度根据操作数量控制在 120px - 180px
```

### 4. 规范要求

规范要求是必须遵守的条目，适合用 checklist 表达。

要求内容通常包括：

- 必须统一的内容。
- 必须限制的范围。
- 必须保留的交互。
- 必须避免的异常状态。
- 必须与其他模块保持一致的规则。

### 5. 使用建议

使用建议不是强制规则，而是帮助设计落地的推荐方式。

常见内容：

- 不同场景下的推荐值。
- 不同复杂度下的处理方式。
- 默认方案与例外方案。
- 设计师和研发协作时的判断依据。

### 6. 视觉示例

视觉示例是设计规范图的核心价值。没有示例的规范图只是文档排版。

示例应尽量贴近真实业务界面：

- 表单：标签、输入框、选择器、按钮、上传、文本域。
- 查询区：筛选项、日期范围、查询/重置按钮、展开收起。
- 表格：表头、列、行、操作列、冻结区、视图控制。
- 弹窗：标题、内容区、操作区、关闭按钮。
- 卡片：标题、数据、状态、操作入口。

### 7. 标注系统

标注负责把规则和界面局部建立关联。

常用标注元素：

- 红色标题：强调问题或规则。
- 编号圆点：建立阅读顺序。
- 虚线箭头：指向对应 UI 区域。
- 测量线：表达宽度、高度、间距、数量。
- 半透明色块：标记区域范围。
- 正误标签：区分推荐与不推荐。

标注必须指向真实对象，不能指向空白或错误区域。

### 8. 边界和例外

好的规范图必须说明边界，否则容易被误用。

常见边界：

- 最大值和最小值。
- 不同页面是否允许差异。
- 超长内容如何处理。
- 响应式下是否沿用桌面端规则。
- 特殊业务场景是否可以例外。

## 三、设计规范图的结构表达

### 结构 1：规则总览型

适合：一条新规范首次说明。

结构：

```text
标题
问题说明
核心规则 / 公式
规范要求
使用建议
视觉示例
边界说明
```

特点：

- 信息完整。
- 适合放进设计规范文档。
- 适合作为团队统一认知的主图。

### 结构 2：场景示例型

适合：规则必须依赖 UI 场景理解。

结构：

```text
标题
一句话规则
大面积 UI 示例
局部标注
关键说明
```

特点：

- UI 示例占比更高。
- 适合解释“规则落在哪里”。
- 适合表单、表格、查询区等复杂组件。

### 结构 3：对比判断型

适合：容易被误解的规则。

结构：

```text
标题
问题说明
不推荐示例
推荐示例
判断原则
边界条件
```

特点：

- 左右对比直观。
- 适合说明“可以不同”和“必须统一”的差异。
- 适合设计评审和研发对齐。

### 结构 4：阈值档位型

适合：包含数字、断点、档位的规范。

结构：

```text
标题
核心公式
数值档位
每个档位的示例
最大/最小边界
使用建议
```

特点：

- 数字是视觉中心。
- 适合标签宽度、查询项数量、表格列宽、间距、字号、断点等规范。

### 结构 5：标注讲解型

适合：基于已有界面截图或复杂组件说明。

结构：

```text
标题
UI 截图 / 组件 mockup
编号标注
说明卡片
重点区域高亮
```

特点：

- 信息附着在界面上。
- 适合改版说明、组件能力说明、复杂后台系统说明。

### 结构 6：流程应用型

适合：规则需要按步骤判断。

结构：

```text
01 问题识别
02 判断条件
03 应用规则
04 示例展示
05 边界处理
```

特点：

- 适合解释设计决策流程。
- 适合复杂规则、响应式规则、组件状态规则。

## 四、不同组件的制图特点

### 1. 表单类规范

重点表达：

- 标签宽度
- 标签对齐
- 输入框宽度
- 必填状态
- 校验状态
- 分组标题
- 长字段处理
- 上传区域

图中建议：

- 使用真实表单行。
- 标签右对齐时要明确标签列范围。
- 输入框只保留边框，避免多余分割线。
- 用测量线说明标签宽度、字段宽度、间距。
- 用省略号示例说明超长标签处理。

常见错误：

- 把间距标注成标签宽度。
- 为了美观添加真实系统中不存在的分割线。
- 标签、输入框、按钮比例失真。

### 2. 查询区规范

重点表达：

- 默认展示几个查询项。
- 超出数量是否收起。
- 查询/重置按钮位置。
- 展开收起入口。
- 响应式断点。
- 查询项顺序是否与表格列一致。

图中建议：

- 用不同宽度的查询栏展示断点。
- 用数字标注默认展示数量。
- 把操作按钮固定在右侧区域。
- 用折叠区说明更多条件。

常见错误：

- 只画输入框，不说明按钮区。
- 查询项顺序和业务读取顺序不一致。
- 响应式变化没有明确断点。

### 3. 表格类规范

重点表达：

- 表头
- 表格列
- 操作列
- 冻结列
- 表头筛选
- 自定义列
- 视图切换
- 拖拽排序

图中建议：

- 保持企业后台表格真实感。
- 冻结列可用半透明蓝色区域标记。
- 表头筛选可用浅绿色标记。
- 工具栏可用橙色标注。
- 操作列应固定在右侧并明确边界。

常见错误：

- 把表格画成营销卡片。
- 标注遮挡关键字段。
- 操作列、冻结列、工具栏混在一起。

### 4. 弹窗 / 抽屉类规范

重点表达：

- 标题区
- 内容区
- 操作区
- 关闭入口
- 宽度规则
- 滚动规则
- 主次按钮

图中建议：

- 明确分区。
- 底部按钮区要稳定。
- 复杂内容要说明滚动区域。
- 用对比说明“弹窗”和“抽屉”的适用差异。

### 5. 卡片 / 数据展示类规范

重点表达：

- 信息层级
- 标题
- 主数据
- 辅助数据
- 状态
- 操作入口

图中建议：

- 用层级标注说明主次信息。
- 避免装饰过度。
- 数字、单位、状态标签要清晰。
